Privacy

Privacy policy.

ScriptWidget stores your scripts and app data on your devices and, when you enable it, in your iCloud account. ScriptWidget does not operate an account service and does not sell personal information.

Scripts and packages you choose to run may request access to device capabilities or network hosts. ScriptWidget presents and enforces package permissions, but third-party scripts and services have their own behavior and privacy practices. Review a package and its requested permissions before installing it.

If you configure an AI provider, requests are sent to the provider and endpoint you select under that provider’s terms. AI provider credentials use the credential storage described for each platform below.

Windows

ScriptWidget for Windows stores widget packages, settings, widget storage, cached downloads, provider settings and AI conversations in your Windows user profile. The standalone application normally uses %LOCALAPPDATA%\ScriptWidget; the Microsoft Store package uses its Windows-managed local application-data folder. Windows does not provide ScriptWidget's iCloud sync features.

Widget code can read the package's own files and, when its package declares the necessary permissions, use package-specific storage, device/system information and network services. Network requests are limited to the hosts the package declares and are checked against private-address and request-size rules. The information a widget sends depends on the code you choose to run. Third-party services receive those requests under their own privacy practices.

When you send an AI request, ScriptWidget sends your request, the current widget entry code, relevant earlier requests and versions, selected Skills, and bounded diagnostic or console-log excerpts to the AI provider and endpoint you configure. Inputs are sent directly by the application to that endpoint. The provider processes them under its own terms and retention controls. Local validation executes candidate code and may make requests to its declared public hosts before you apply it to the installed widget. Validation uses temporary widget storage; it does not pass the installed widget's saved $storage values to the provider as an attachment. Code and log excerpts may themselves contain information you have placed in them.

Provider API keys are kept in Windows Credential Locker and used to authenticate provider requests. They are not included in widget exports, provider-settings JSON, AI conversation files or model prompts. Windows manages the locker; credential roaming may depend on your Windows account and settings, as described in Microsoft's Credential Locker documentation. Removing a provider in Settings requests removal of its key and reports failures. The standalone uninstaller does not explicitly clear Credential Locker entries, so remove provider profiles before uninstalling if you want the application to remove their keys.

You can choose an Ollama or LM Studio server running on this computer. These local AI connections use the OpenAI-compatible API and may use HTTP on localhost, 127.0.0.1 or the IPv6 loopback address; an API token is optional unless your server requires it. Local connections bypass system proxies and are confined to loopback. The server software and model you choose determine how inputs are processed; selecting a local server does not guarantee that the server itself avoids external services. Remote AI endpoints require HTTPS and an API key. Candidate widget code can still make its own declared network requests during validation.

Gallery browsing downloads the shared catalog from ScriptWidget's configured GitHub raw-content root. Installing a Gallery item downloads and verifies its declared files. Widget packages and Skills you import remain on your device unless you export them or their code makes a permitted request. Skills are prompt text and do not execute native code or grant additional access.

You can inspect local application files from Settings using Open folder. Conversations remain locally until removed from that folder or pruned by the application's history limits. Cancel stops an active AI request in the application; it does not delete information a provider has already received. Removing local files or a provider profile does not request deletion from that provider. The standalone uninstaller offers a choice about retaining local widget data; a silent uninstall retains it. Windows manages removal of Microsoft Store package data.

Linux

ScriptWidget for Linux (a preview for Omarchy) stores widget packages, settings, widget storage, Skills, the Gallery installation record, provider settings and AI conversations in your user data folder, normally ~/.local/share/scriptwidget, and downloads in ~/.cache/scriptwidget. There is no account and no iCloud sync. The application contains no analytics or advertising code. Widget code can read the package's own files and, when its package declares the necessary permissions, use package-specific storage, device/system information and network services. Network requests are limited to the hosts the package declares and are checked against private-address and request-size rules. The information a widget sends depends on the code you choose to run, and third-party services receive those requests under their own privacy practices.

When a widget is allowed to, it can read the track your media player reports (through MPRIS), post desktop notifications, read files and pictures you choose for that widget, and, after you connect GitHub, make requests with your GitHub token. Files and pictures are read from where you keep them when the widget runs; the GitHub token is stored in your desktop keyring (Secret Service) and is not included in widget exports or settings files.

When you send an AI request, ScriptWidget sends your request, the current widget code, relevant earlier requests and versions, selected Skills, and bounded diagnostic or log excerpts to the AI provider and endpoint you configure, directly over HTTPS; redirects are not followed. The provider processes them under its own terms. Code and log excerpts may themselves contain information you have placed in them. Provider API keys are stored in your desktop keyring (Secret Service, for example GNOME Keyring or KeePassXC) through secret-tool, and are not included in widget exports, provider settings, AI conversation files or model prompts. Without a keyring no key is stored. Removing the key in Settings or with scriptwidget ai key remove deletes it from the keyring; uninstalling does not.

Gallery browsing downloads the shared catalog from ScriptWidget's configured GitHub raw-content root, and installing an item downloads and verifies its declared files. Conversations remain locally until you remove them. Removing local files or a provider profile does not request deletion from that provider. sh uninstall.sh keeps your data folder; sh uninstall.sh --purge deletes it and the cache.

Android

On Android, ScriptWidget stores your scripts and app data on your device. There is no account. If you pick a shared folder for sync, files are stored with the storage provider you choose, under that provider’s policies.

Location, calendar, photos, contacts and Health Connect data (steps, active calories, distance, exercise, sleep, heart rate, hydration and weight) are read only after you grant the Android permission and allow the widget package to use them. They are read on your device to draw your widgets, including when widgets refresh in the background. ScriptWidget does not send this data to us, does not use it for advertising and does not write to Health Connect. A widget you install can send data only to the network hosts its package declares, which the app shows before use.

ScriptWidget uses Firebase Cloud Messaging so that widgets which declare push updates can refresh when their server sends a message. For this, Google assigns the app installation a messaging token (a device identifier) and processes it under Google’s policies. If a widget package you install declares push updates, the token is sent to the registration server that package declares. The app contains no advertising or analytics SDK and does not use the advertising ID.

On Android, AI provider credentials are stored encrypted with the Android Keystore. Google may process Google Play downloads and diagnostics under Google’s policies. Removing the app deletes its data from the device.

Apple platforms and contact

On Apple platforms, AI provider credentials are stored using Apple platform security facilities.

Apple may process App Store downloads, purchases, diagnostics, and iCloud data under Apple’s policies. For privacy questions, contact atomsprout@gmail.com.
